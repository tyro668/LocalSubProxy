01

设计结论与适用边界

默认支持每位 SaaS 用户连接自己的电脑，同时为企业共享的内网模型保留独立部署形态。

CONNECTION

本地主动出站

连接器通过 WSS 443 连接 SaaS；必要时降级为 HTTPS 长轮询。本地模型端口不对公网发布。

EXECUTION

任务驱动执行

云端创建任务，本地执行器按固定适配器处理。流式事件、取消和人工审批均纳入同一任务协议。

OWNERSHIP

账户按用户隔离

设备绑定租户与所有者；个人订阅默认只服务本人。组织共享模型使用专门配置和授权。

方案状态：研发评审稿 v1.0。用户已选定本地连接器路线；具体模型产品、操作系统覆盖、并发规模尚未指定。下文明确区分“建议默认值”“待验证能力”和“官方事实”，所有容量与工期数字均为规划假设。

02

场景与账户模式

把“模型在哪里推理”和“由谁的账户付费”作为两个独立属性。

用户自己的 SaaS 任务 → 本地连接器 → 官方客户端 → 模型厂商云端

账户模式：个人。登录由官方客户端完成；云端不取得厂商登录凭证。任务消耗所属账户权益，是否可集成取决于官方接口与产品条款。电脑在线和厂商服务可达均是前提。

用户自己的 SaaS 任务 → 本地连接器 → 本机推理服务

账户模式：个人。使用已下载的本地模型时，推理发生在设备内；SaaS 已持有的任务输入和回传结果仍经过云端。模型安装、内存和 GPU 容量由本地环境决定。

授权员工的 SaaS 任务 → 企业网关连接器 → 企业内网模型接口

账户模式：组织。连接器作为受管服务运行在常开服务器上；由管理员配置模型和访问组。使用企业自有模型或明确允许共享的商业推理服务，避免把个人订阅转为全员共享资源。

运行身份当前操作系统用户，访问其已授权运行时专用服务账户，禁止借用普通员工登录态
设备可见性本人可用；管理员可禁用，不能冒用个人订阅管理员配置访问组；调用者看逻辑模型而非服务器细节
计费归属个人订阅 / 个人 API / 本地算力企业模型服务 / 企业 API / 企业算力
推荐并发初值每设备 1；由适配器和额度进一步限制按已测得的模型并发上限配置，不按在线人数推定
离线策略提示上线或排队，设置队列过期时间服务健康检查 + 网关实例池 + 受控故障转移
订阅权益、模型调用能力、安装位置是不同概念。产品配置应分别存储 account_scope、inference_location 与 adapter_type，不能由“地址是 localhost”推断数据不会发送到模型厂商。
03

总体架构与信任边界

云端负责“谁可以运行什么”，本地负责“在这台机器上允许做什么”。

箭头表示调用或建连方向；响应沿原通路返回。厂商云端位于本地信任边界之外；使用纯本地模型时无需这一推理路径。
层职责不承担的职责
SaaS 任务 API校验登录用户、业务对象权限、模型选择、预算；创建任务不将客户端传入的 tenant_id 或 user_id 作为授权依据
调度器按租户、用户、设备、能力和会话亲和性路由；创建 attempt不因为连接断开就直接重跑正在执行的任务
连接网关管理在线连接、认证、协议协商、背压、命令投递不保存唯一一份任务事实；不执行模型推理
任务与事件存储保存任务状态、事件序列、幂等键、审批记录不默认记录厂商原始输出中的全部内部元数据
连接器核心身份、策略、收发、持久化 journal、子进程管理不接受云端任意可执行路径、任意参数或任意本地 URL
适配器把统一任务转换为已允许的模型调用；归一化事件不绕过厂商鉴权，不伪造 token 用量和额度
官方运行时 / 本地模型实际推理，可能包含自带工具执行循环不能假定每个运行时都有相同的沙箱、取消和恢复语义
分开管理两组凭证：SaaS 设备凭证由你的平台签发；模型厂商凭证由官方客户端或本地凭证库持有。云端只保存运行时登录状态和允许展示的账户标签，不保存厂商订阅 token。

推荐调用链

  1. 用户在 SaaS 选择业务上下文和本地模型，云端按既有业务权限构造任务。
  2. 任务与派发 outbox 在同一数据库事务落库，调度器为可用设备创建执行尝试。
  3. 网关在已建立的连接上下发任务；连接器验证权限和期限，持久化后 ACK。
  4. 连接器申请执行许可，持久化执行意图，启动适配器并逐段上传事件。
  5. 云端持久化事件后确认接收，再向浏览器发送 SSE。完成状态与最终结果引用原子提交。

用户流程与产品界面

首次配置控制在“安装 → 绑定 → 选择运行时 → 测试”四步，日常使用留在 SaaS 页面。

  1. 安装并登录连接器

    用户下载签名安装包，连接器打开 SaaS 官方登录与设备绑定页；页面显示设备名、绑定组织和校验短码。

  2. 选择本地模型或官方客户端

    只检测用户允许的安装位置与已配置地址。订阅客户端通过官方流程登录；配置本地模型时检测接口和模型列表。

  3. 完成一次小任务测试

    展示网络、运行时、任务执行和结果回传四项状态。模型调用测试会明确提示可能消耗额度；被动检测不自动发送推理请求。

  4. 在 SaaS 中使用

    用户选择设备与模型后提交任务。页面展示等待、运行、待审批、完成状态；可取消、查看结果、重新登录或切换设备。

组件拆分与技术栈

优先复用已有 SaaS 与桌面技术栈。通信协议保持语言无关，避免为连接器引入整套新平台。

组件推荐实现关键设计
SaaS 控制面复用现有 Java / Spring Boot 服务增加设备、任务、策略 API；不因本方案强制升级框架
接入网关Java 异步网络栈 / 现有网关体系长连接独立扩容；按连接映射路由；发布时先排空
任务调度数据库任务表 + outbox worker 起步有规模证据后接入既有消息队列；消费者始终幂等
事实存储PostgreSQL 或现有关系型数据库任务状态和事件事务提交；唯一约束处理幂等
在线映射 / 限流Redis 或既有缓存在线映射带 TTL 和 session_epoch；丢失可重建
本地核心已有 Java 桌面体系时采用 Java 常驻核心WebSocket / HTTP、SQLite、OS 凭证库、子进程 supervisor
桌面界面已有 Electron + React 桌面助手可直接复用renderer 不持有密钥；界面与本地核心走受限 IPC
独立轻量发行无既有桌面产品时，可评估 Rust + Tauri这是替代实现，不要求同时维护两套连接器
本地 journalSQLite WAL；敏感内容应用层加密WAL 本身不加密；密钥存 OS 凭证库，备份与清理统一处理
文件传输现有对象存储 + 短期作用域凭据大文件不走 WebSocket；校验大小、类型和 SHA-256

本地进程边界

  • 界面进程：设备绑定、运行时配置、审批、状态和诊断。关闭窗口不等于停止后台连接器。
  • 连接器核心：拥有设备凭证与本地 journal；负责校验和调度。通过固定方法的 IPC 接收界面操作。
  • 适配器子进程：按任务 / 会话启动。限制环境变量、工作目录、输出大小和运行时间；回收整个进程组。
  • 官方运行时：优先保留其官方安装、登录、审批和更新机制；版本兼容性由适配器测试矩阵管理。
MVP 可将任务 API 与调度器部署在现有服务内；接入网关独立进程部署。本地 UI 与核心分离是权限与生命周期边界，不代表必须采用微服务。

设备绑定、认证与授权

SaaS 身份、设备身份、模型账户身份分别验证，彼此不能替代。

首次绑定时序

  1. 连接器生成设备密钥

    通过成熟密码库生成设备密钥对；私钥存 OS 安全存储或其保护的加密密钥文件，限制当前运行账户访问。硬件不可导出密钥作为企业增强选项。

  2. 创建待绑定请求

    上传公钥、随机 nonce、设备名、系统版本和连接器版本。服务端返回 enrollment_id、短码、绑定页地址和独立的高熵轮询凭据；建议 5 分钟过期。

  3. 用户在 SaaS 确认

    通过 SaaS 自身登录态确认组织、设备名、公钥指纹和使用范围。短码只是定位请求；凭短码不能领取设备凭证。提交操作校验 CSRF。

  4. 设备领取凭证

    连接器使用轮询凭据并签署服务端挑战，证明拥有绑定公钥。服务端原子完成单次领取，颁发短期设备访问令牌和设备密钥绑定的续期凭据。

  5. 建立受认证连接

    连接器通过 Authorization 头提交访问令牌；网关验证签名、过期时间、用途、设备版本和撤销状态，然后分配 session_epoch。

凭据 / 信息存储位置建议生命周期与范围
SaaS 用户登录态浏览器安全 Cookie / 现有认证体系沿用平台会话政策；任务 API 做 CSRF 与业务权限验证

运行时授权

最终可执行权限取 租户策略 ∩ 用户授权 ∩ 设备本地策略 ∩ 适配器能力。任一层拒绝即停止。默认每台个人设备只绑定一个租户与所有者；切换组织需显式解绑并重新绑定，不能直接把原账户会话带到新租户。

每个任务附带短期、明确受众的执行授权，包含 task_id、attempt_id、设备、允许动作、输入摘要、策略版本、到期时间。连接器验证其签名及本地授权记录；云端管理员拥有禁用权，不自动拥有代用户调用个人订阅的权利。

续期与撤销：长连接不应绕过令牌过期。到期前发送受认证续期消息并重新校验；不能续期时停止接收新任务。撤销后网关主动断开并拒绝重连；已在离线本机执行的第三方操作无法保证立即停止，按租约到期策略处理。

上述绑定端点是本产品协议，不冒充模型厂商 OAuth。密码学签名、JWT 验证和密钥轮换使用成熟库；企业要求更高设备身份保障时可在第二阶段引入 mTLS。

连接生命周期与网络适配

连接在线、运行时健康、模型可调用是三个独立状态，页面和调度器分别判断。

状态主线：UNBOUND → AUTHENTICATING → CONNECTING → READY；断网进入 RECONNECTING，主动暂停进入 PAUSED，撤销进入 REVOKED。只有 READY 且适配器健康、存在空闲槽位时接受新任务。

环节处理方式建议初值 / 约束
出站连接连接器访问固定网关域名的 WSS 443；传输层采用 TLS验证域名与证书；不提供“忽略证书错误”的生产开关
握手发送 hello：协议版本、能力清单、journal 状态与最后确认位置服务端选择兼容版本；不兼容时明确要求升级
心跳应用层 heartbeat 上报健康、空闲槽位、运行 attempt、最后命令序号25 秒一次；75 秒无有效活动标记离线；同步配置负载均衡空闲超时
长连接令牌续期在旧令牌过期前重新验证新令牌；更新授权上下文15 分钟令牌，提前约 2 分钟续期；失败后停止新调度
断线重连指数退避并加全抖动，先确认网络恢复再发起连接上限序列 1、2、4、8、16、30 秒；成功稳定运行后重置
连接世代每次连接成功由服务端生成递增 session_epoch同一设备只保留一个当前控制会话；旧连接不能改变任务状态
网络降级WSS 多次握手失败且识别到代理限制后，采用 HTTPS 长轮询建议 25 秒等待；事件通过批量 POST；保持相同幂等和顺序语义
企业代理支持系统代理 / 明确配置的 HTTP CONNECT 代理代理凭证留在本地；TLS 检查使用企业正式分发的信任链
休眠唤醒监听系统事件，唤醒后重新鉴权、重建连接、对账任务不能只靠旧 socket 判断在线；不承诺休眠中持续执行
退出与暂停暂停停止新任务；退出时询问正在运行任务的处理方式托盘退出和窗口关闭区别展示；组织服务由管理员策略控制
session_epoch 与 fence_token 不同：前者阻止旧网络连接发送新命令或状态；后者阻止旧任务尝试覆盖当前尝试。重连提升 session_epoch，不自动创建新 attempt，也不自动重启模型。

恢复握手

  1. 设备发送运行任务列表、每个 attempt 的最后本地事件 seq、已收到的云端 ack_seq，以及运行时恢复标识。
  2. 服务端返回每个 attempt 的当前状态、已持久化 ack_seq、有效租约和待处理取消 / 审批决定。
  3. 连接器只重传未确认事件；重复 seq 由服务端唯一约束去重。已终止的 attempt 不能恢复为运行中。
  4. 重连不会自动重放启动命令。若服务端记录与本地 journal 冲突，进入 RECONCILING 状态，由对账规则决定后续动作。

WebSocket 提供双向消息传输；持久化、重放、任务幂等与断点恢复是本产品额外实现的协议能力。[1]

任务状态机与执行一致性

将“请求被接受”“已经开始执行”“结果已经持久化”设置为不同的确认点。

状态进入条件允许转移 / 页面含义
QUEUED创建任务成功，尚未分配执行尝试DISPATCHED / CANCELLED / EXPIRED；可等待设备上线
DISPATCHED已为设备分配 attempt 并投递命令ACCEPTED / RECONCILING / EXPIRED；尚不能宣称运行中
ACCEPTED本地校验成功并持久化接受记录RUNNING / CANCELLED / EXPIRED；等待执行许可
RUNNING执行许可有效，已记录执行意图并启动调用WAITING_APPROVAL / CANCEL_REQUESTED / SUCCEEDED / FAILED / RECONCILING
WAITING_APPROVAL运行时提出受支持的工具审批RUNNING / CANCEL_REQUESTED / FAILED；审批等待计入总时限
CANCEL_REQUESTED云端已接受取消请求CANCELLED / SUCCEEDED / FAILED / RECONCILING；此时尚未证明终止
RECONCILING断连、进程崩溃或上游结果不明确恢复到已证实状态，或转 UNKNOWN；禁止自动重放有副作用任务
SUCCEEDED / FAILED最终结果或已知失败被云端持久化终态不可被迟到事件反转；重跑需新任务或明确新 attempt
CANCELLED / EXPIRED确认执行已停止，或证明尚未执行且过期终态；过期必须区分排队过期与运行超时
UNKNOWN无法确定上游是否已执行或完成自动化停止；保留证据，用户明确选择新任务重跑

三个确认点

  1. 接受 ACK：连接器完成权限校验，将 (task_id, attempt_id, payload_hash) 与状态写入本地 journal，提交成功后发送 ACCEPTED。相同标识与摘要重复投递时只重发当前状态；摘要不一致直接报协议冲突。
  2. 执行许可：连接器向云端申请 start_grant。云端通过条件更新核验当前 attempt、取消状态、fence_token、设备槽位和租约；签发短时许可。本地先持久化启动意图，再调用运行时。
  3. 结果确认：本地先持久化最终事件与结果摘要，再上传；云端原子提交终态及结果引用后 ACK。未收到 ACK 时允许重复上传同一结果，不重复调用模型。
无法消除的崩溃窗口：写入“准备启动”之后、收到上游明确回执之前发生崩溃，可能无法判断厂商是否已接受请求。先尝试通过官方 session / run 标识恢复；无查询能力时标为 UNKNOWN。不能仅凭本地没收到输出就自动再次发送。

租约、去重与重试策略

机制设计
用户提交幂等按 tenant_id + user_id + Idempotency-Key 建唯一约束；建议保存 24 小时。相同键不同输入返回 409；同键同输入返回原 task_id。
尝试级防重task_id 可有多个 attempt；同一时刻最多一个获准执行的 attempt。fence_token 单调递增；存储更新使用当前 token 与版本 CAS。
执行许可期限start_grant 建议 30 秒内使用；run lease 建议 120 秒，每 30 秒续期。云端失联时停止启动新的外部动作；到期后请求停止运行时并记录执行是否可确认终止。
纯推理重试只在确认未启动 / 明确可重试失败时默认重试，建议最多 2 次自动重试。未知结果重试需用户同意可能重复消耗额度；每次用新 attempt。
有副作用任务默认不自动换机重试。必须有业务幂等键、隔离执行或可查询的外部事务标识，才可针对该动作开放恢复。
租约到期租约过期只表明执行权到期，不能证明厂商已停止工作。fence 保护云端状态，无法替代外部系统幂等。
会话亲和性运行时会话绑定 tenant + owner + adapter + device；同一会话串行写入。设备切换须新建会话或通过明确受支持的迁移流程。
取消竞争若完成已经事务提交，取消返回 already_completed；若仅取消请求先到但模型已完成，返回真实终态和 cancel_outcome，不伪造已取消。

每个 attempt 的 seq 从 1 严格递增，唯一键为 (attempt_id, seq)。服务端只有连续事件都已持久化，才返回累计 ack_seq；发现缺口请求重传，重复事件内容不同则报告完整性冲突。网关进程内存接收成功不能代替持久化 ACK。

9.4 背压与终态

连接器为每个任务设置发送窗口与本地 spool 上限。建议单任务缓存 10 MiB、设备总缓存 200 MiB；达到上限时，能暂停读取则暂停，不能暂停时请求取消并上报 OUTPUT_LIMIT_EXCEEDED，不静默截断最终答案。超大产物通过文件通道传输。最终事件中包含 output_artifact_id、sha256、usage、usage_source 和 completion_reason；用量未知时设 null。

适配器调用方式支持策略
本地 Ollama配置地址的 HTTP API；GET /api/tags、POST /api/chatV1 基础适配器。模型是否本地推理由实际模型配置确认，不能只看 localhost。[2][3]

  • 能力协商：区分 chat.generate 与 agent.run。纯模型接口返回 tool_calls 时，V1 只返回结构化提议；没有执行编排器时不自动执行工具。

审批模型

审批请求绑定 approval_id + task_id + attempt_id + action_hash + policy_version + expires_at。展示将读取 / 修改的文件范围、命令或外部动作，不只显示“是否允许执行”。决定一次性生效，动作参数变化必须重新审批。V1 无危险工具时可不出现审批 UI；Agent 阶段才启用。

本地文件修改和命令执行默认在本地连接器 / 官方可信界面审批。SaaS 页面审批仅适用于企业明确允许的受控动作，不作为防范云端失陷的唯一屏障。审批机制无法拦截的运行时动作不纳入支持范围。

异常恢复与降级策略

所有自动恢复都应先回答“任务是否已经执行”，再决定是否重试。

故障连接器动作云端与用户体验
设备尚未收到任务就离线重连后从待确认命令恢复；过期命令拒绝保留 QUEUED / DISPATCHED；不能自动把个人任务路由给他人
接受 ACK 丢失根据 journal 返回同一 attempt 的当前状态重复投递不新增运行时调用
收到任务后立即崩溃恢复 journal；有启动意图则先对账无法证明未执行时进入 RECONCILING / UNKNOWN
流式输出中断网在上限内加密缓存，按租约限制继续执行；到期请求中断显示连接中断；重连按 seq 补传，避免重复显示正文
结果已生成但完成 ACK 丢失重复提交同一最终事件与摘要云端重复结果只确认，不重新计数和创建新结果
连接器重启但子进程仍存在通过受管进程组 / 运行时标识识别并恢复或终止不能只用可能复用的 PID 认领进程；未知时不新开同一任务
用户电脑休眠唤醒后重建连接并检查运行时状态显示离线；任务期限继续由云端计算，不能因唤醒重置预算
厂商登录过期标记 AUTH_REQUIRED，停止该适配器新任务提示本机重新登录；不把登录失败转换成另一账户调用
额度耗尽 / 速率限制区分 quota 与 rate limit；只采用可信 retry_after用户明确选择后方可换来源，显示可能产生新的费用
运行时超时 / 卡死先中断，建议 10 秒宽限后终止受管进程组记录停止是否确认；不能确认上游终止时标 UNKNOWN
取消与完成同时发生上传真实完成状态与取消响应按事务提交和运行时事实显示完成或取消，不丢弃已完成结果
本地磁盘满 / 缓存超限停止接单；无法持久化就不 ACK；中止受影响任务显示存储不足及清理入口；禁止默默转为不可靠内存模式
网关节点重启连接器随机退避重连，取得新 session_epoch任务状态不丢失；旧连接事件通过世代与 fence 校验拒绝
数据库不可用缓冲在既定上限内；云端不返回持久化 ACK暂停新任务接受 / 派发；恢复后按幂等协议重传
协议或运行时版本不兼容保持设备可见，禁用受影响适配器明确升级 / 回退路径；其余兼容适配器仍可用
设备撤销时离线下次连接拒绝；本地执行租约到期后请求停止立即阻止新任务；显示已有任务可能尚未确认停止
默认关闭自动付费降级。换模型、换账户和换设备都会改变数据接收方、费用与结果特征。允许降级时必须由用户事先配置来源、费用上限与数据范围，并在任务记录中保留原始来源和实际来源。

文件、会话与数据分析场景

先将输入变成有权限、有大小上限、可追溯的任务资源，再交给模型。

文件处理链路

  1. 生成资源：SaaS 为已有业务附件生成 task artifact 引用；用户本地文件通过文件选择器显式授权，不能靠云端给出路径来读取。
  2. 发放权限：设备获得仅针对本次任务的下载 / 上传许可，建议 5 分钟过期，限定方法、对象、最大字节数和内容类型；过期后重新鉴权领取。
  3. 下载与校验：本地按流下载并核对大小和 SHA-256，保存到隔离任务目录。初始上限可设单文件 20 MiB、每任务 5 个文件，之后按场景实测调整。
  4. 解析与调用：先校验文件格式与实际 MIME。压缩包限制层级与解压后大小；解析器采用受限进程。模型不支持附件类型时通过可信转换流程转成文本，明确可能有截断。
  5. 返回产物：先上传临时对象并核验摘要，再原子提交结果引用。失败或取消产生的孤立对象由清理任务回收。

会话管理

平台 session_id 与厂商 runtime_session_id 分离存储，后者仅由对应设备适配器管理。同一会话串行提交；用户切换模型或设备时明确提示会话重建。云端负责保存获准留存的对话上下文，并在上下文超限时使用可见的摘要策略，不依赖不同厂商隐藏的会话记忆。

历史权限可能变化。继续对话前重新校验当前用户对数据快照和附件的权限；已撤销权限的数据不能因出现在旧会话里而继续发送给模型。下载过的历史副本无法远程保证物理删除，因此仍需本地生命周期与企业终端治理。

关键事务

  • 提交：校验幂等记录 → 写 llm_tasks → 写 outbox → 写幂等映射，统一提交。
  • 派发：对任务状态条件更新，分配当前 attempt 与 fence_token；派发记录与状态更新同事务。
  • 接受事件：核验当前 attempt / fence → 插入唯一事件 → 更新连续确认游标；提交后 ACK。
  • 完成：验证最终结果摘要和文件状态 → 更新 task / attempt 终态及结果引用 → 提交后向连接器和 UI 确认。
  • 撤销设备：提升 auth_version → 停止新路由 → 发布断开命令；离线的已运行任务保留“待确认停止”状态。

关系表、对象存储与厂商运行时之间不存在天然跨系统事务。用 outbox、暂存对象、幂等操作和补偿清理闭环处理；不把 MQ 的投递确认等同于业务执行完成。
